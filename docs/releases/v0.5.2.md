## What's new

- **An icon that matches the app:** the waveform icon now uses the interface's plum/rose gradient and light bars. Desktop, Windows tray/audio identity, and Android launcher assets share the refreshed palette.
- **Build a queue from popup search:** press `Ctrl+Shift+K`, select a song, then `Shift+Enter` to play next or `Ctrl+Enter` to add to the end. The same actions are available as buttons. Additions keep the popup open and confirm the song; failures stay visible for retry.
- **Optional automatic lyrics:** enable **Automatically find lyrics** in the lyrics window to follow new songs. The switch defaults off when the panel is created. Up to 20 successful lookups stay in that window's memory, and **Refresh lyrics** bypasses the cache. Instrumental tracks get a clear status; advertisements do not trigger lookups.
- **Copy the current song's link:** use **Copy song link** in the player for a local or remote track. Confirmation appears after a successful copy, and clipboard errors remain visible. Links contain the song identifier without private collection context.

## Fixes

- Prevent obsolete lyrics results and errors from overwriting the current song, including when returning to a previously selected song.
- Keep remote lyrics visible during unrelated local-player updates and reset them when the playback source changes.
- Let controllers with queue permission add songs without transport permission, while keeping immediate playback and selection restricted.

## Verification and limits

The audit passed 131 automated tests across the desktop interface, player bridge, protocol, relay, and Rust workspace. One hardware-dependent multicast smoke test remains skipped. Browser checks covered the new lyrics and popup actions, the minimum popup size, and song-link copying using mocked playback data. Live YouTube playback and physical-device acceptance were not repeated for this audit; release builds run the repository's full CI again.

Lyrics lookups send the track title, artist, and rounded duration to LRCLIB on request, or for new tracks while automatic lookup is enabled. Availability and version matching depend on LRCLIB's catalog. The cache is temporary and does not restore a listening session after restart.

## Downloads and updating

Downloads include Windows EXE/MSI, macOS DMG, Linux AppImage/DEB, an experimental Android arm64 APK, and `SHA256SUMS.txt`. Verify downloads against the checksum file. Fully quit YTM Listen from its tray menu before installing the Windows update.

Desktop installers are unsigned. Windows is the primary verified development target; macOS and Linux still need native behavior testing. Android remains experimental: Google library access requires APK-specific OAuth registration, and authenticated Music playback and physical-device/background acceptance remain pending. The APK uses a test signing key. The Windows virtual microphone remains a preview requiring an installed virtual cable and hardware acceptance.
