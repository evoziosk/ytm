### Global quick search

The compact local search window uses a configurable Ctrl+Shift+K global shortcut.
It opens centered above other applications on the pointer's display, stays
out of the taskbar, focuses the search input, and hides on focus loss, Escape,
or successful selection. Search requests are debounced and coalesced; an older
response cannot overwrite a newer query. Arrow keys wrap through song results,
Enter plays the selected item, and IME composition does not trigger playback.
Playback errors stay visible and party guests cannot change the host's music.
The tray and Keyboard shortcuts page also open the overlay. Existing settings
automatically gain the new configurable shortcut without resetting preferences.

The overlay uses a transparent WebView and page background, a translucent glass
panel, and native Windows Acrylic desktop blur. Centering uses the monitor work
area in physical pixels, including display scaling and negative monitor coordinates.

Final packaged 0.3.0 checks passed: the global quick-search shortcut registered,
the frameless overlay opened above other apps, and its physical position matched
the center of the display work area. Playback progressed on the requested song,

134 kbps with High requested. All 61 automated tests, type checks, formatting
checks and Rust Clippy passed. The Windows installer is
`YTM Listen_0.3.0_x64-setup.exe` (3,462,867 bytes).

## Version 0.3.2

The Windows volume mixer now receives the YTM Listen name and icon for the
playback engine's audio sessions. The existing application icon is valid:
Windows Shell extraction renders the expected mint waveform logo. The issue
was the audio session inheriting WebView2's identity.

The update obtains process IDs from the playback WebView's own environment,
then updates only matching Windows audio sessions. It does not change session
volume or mute state. All active output devices are checked every two seconds,
so new sessions, device changes and playback-engine restarts receive the same
identity. Unavailable devices are retried without blocking playback.

The implementation follows Microsoft's
[audio-session icon API](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessioncontrol-seticonpath),
[display-name API](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessioncontrol-setdisplayname),
and [WebView2 process enumeration](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2environment8).

An isolated native check read back one real Windows audio session with name
`YTM Listen` and the expected icon path. Playback progressed, and three seeks
were acknowledged in 123, 124 and 140 ms with stable positions. The check paused
playback and exited successfully. Rust tests (19), Clippy, type checks and
formatting checks pass.

The packaged 0.3.2 executable repeated the Windows check successfully: one
playback audio session reported `YTM Listen` with the expected icon. Real
playback progressed, then paused before exit (code 0). The installer is
`YTM Listen_0.3.2_x64-setup.exe` (3,483,924 bytes).

## Android native Google library — 20 October 2026

Implemented Google Play services authorization with native account selection and
read-only YouTube playlist APIs. Kotlin owns authorization and Google API requests;
tokens are not exposed to the playback page or Svelte. Android's guest playback
account events cannot replace the native library account. The catalog routes
library and native playlist IDs without depending on the playback WebView being
signed in. Disconnect invalidates pending authorization/library results and requests
Google grant revocation.
